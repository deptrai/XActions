🎰 Pump.fun Authentication — Browser Bridge

Pump.fun uses Privy auth (Google OAuth + embedded Solana wallet). XActions does not re-implement Solana signing — instead it reuses a session you're already logged into via the Browser-as-Signer / CDP bridge. See docs/architecture/adr-pumpfun-auth-and-dependencies.md.

When do I need this?

Public reads (mint social, platform feeds, live chat history) work without auth. These actions need a session:
  • fetch_my_profile, fetch_user_following
  • fetch_livestream_clips, post_mint_reply
  • livestream-api.pump.fun/kols (Bearer-gated)

Connect a session

  1. Open pump.fun in Chrome and sign in (Privy).
  2. Keep the tab open. XActions extracts privy:token (Bearer JWT), privy:id_token, decoded-jwt (userId, wallet) and cookies (_cfuvid, __cf_bm) via Chrome MCP / CDP.
  3. The bridge registers the session into globalSessionManager under key pumpfun:<accountId>.
  4. Headless requests then attach Authorization: Bearer <jwt> + cookies automatically.
⚠️ Session expiry. JWTs expire. If calls return XACT_4010, re-extract the session from an active pump.fun tab.

Disconnect & revoke

To clear stored credentials:
  1. Log out of pump.fun in the browser tab to invalidate the server-side Privy session.
  2. In XActions, the session is held in-memory in globalSessionManager under pumpfun:<accountId> — restart the service or clear the key programmatically: 
    import { globalSessionManager } from 'xactions/core';
globalSessionManager.delete('pumpfun:default');
  3. Revoked sessions will receive XACT_4010 (Unauthorized) on subsequent calls.

Verify it's working

POST /api/platform/pumpfun/scrape
{ "action": "fetch_my_profile" }
# → 200 { ok:true, result:{ username, address, userId, is_pump_user } }

Rate limits

post_mint_reply is capped at 5 comments / minute / account to protect the wallet from shadowban.
