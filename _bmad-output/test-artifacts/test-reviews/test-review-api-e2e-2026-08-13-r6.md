## Best Practices Found

### BP1. Explicit `TEST_SCOPE` constants replace stack parsing

**Files**: All 7 test files (e.g. `tests/e2e/api-auth.test.js:9-10`, `tests/api/facebook-automate-routes.test.js:18-19`, `tests/e2e/api-operations.test.js:14-15`)

```js
const TEST_SCOPE = 'e2e-api-auth';
// ...
it(`[${nextTestId(TEST_SCOPE, 'E2E', 'P2')}] ...`, ...)
```

This removes the `Error().stack` dependency and makes the ID namespace explicit, stable, and searchable.

### BP2. Factory-driven Facebook profile and group URLs

**Files**: `tests/api/facebook-routes-integration.test.js:12-15`, `tests/api/facebook-automate-routes.test.js:13-16`, `tests/e2e/api-facebook.test.js:13-16`

```js
import { makeFacebookPostUrl, makeFacebookProfileUrl, makeFacebookGroupUrl } from '...';
// ...
.send({ action: 'profile', url: makeFacebookProfileUrl() })
```

All previously hard-coded `https://facebook.com/test`, `https://facebook.com/somepage`, and `https://facebook.com/groups/test` URLs are now generated by deterministic factories.

### BP3. Deterministic, per-fork ID counter

**File**: `tests/utils/test-ids.js:1-11`

```js
const counters = new Map();

export function nextTestId(scope, level, priority = 'P2') {
  const key = `${scope}::${level}`;
  const next = (counters.get(key) || 0) + 1;
  counters.set(key, next);
  return `5.5-${scope}-${level}-${String(next).padStart(3, '0')} @${priority}`;
}
```

The counter is local to the module, and because Vitest runs each file in a fork, cross-file collisions are impossible while repeated runs of the same file still produce the same IDs.
