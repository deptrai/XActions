# Epic 46 Context: Chuẩn Hóa Bộ Hợp Đồng API & Tài Liệu Tương Tác OpenAPI 3.1 / Swagger

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Standardize all in-scope Express backend routes (scope defined by the epic's Route Inventory appendix in `epics.md`) onto a single OpenAPI 3.1 document generated from Zod schemas — one source of truth driving runtime validation, the published spec, and a generated TypeScript client. The epic delivers self-hosted Swagger UI at `/api-docs`, a `GET /openapi.json` endpoint, and a `packages/api-client` package (`@xactions/api-client`) so the Next.js frontend (Epic 47) calls the API type-safely.

## Stories

- Story 46.1: Swagger UI & OpenAPI 3.1 JSON publication endpoint (`/api-docs`, `/openapi.json`)
- Story 46.2: Contract foundation + pilot mounts — Zod schemas, `validate.js`, `envelope.js`, session-cookie shim, registry→spec builder, CI harness; pilot: `/api/viral`, `/api/crm`, `/api/optimizer`, `/api/checkpoints`, `/api/session`, `/api/auth`
- Story 46.3: TypeScript API client generator (`@xactions/api-client` via `npm run generate:api-client`)
- Story 46.4: Rollout batch social/user-facing mounts (twitter, facebook, posting, messages, engagement, graph, profile, ...)
- Story 46.5: Rollout batch data/ops/admin mounts (a2a, workflows, admin, datasets, analytics, governor, video, ...) — completes Route Inventory coverage

## Requirements & Constraints

- The spec is generated from Zod schemas via `@asteasolutions/zod-to-openapi`; the existing `api/openapi.js` (~4.6k lines, currently serving `/api/ai/*`) is refactored into the shared builder — no parallel hand-maintained spec, no hand-edited `paths`.
- `GET /openapi.json` returns `200` with `openapi: 3.1.0`, keeps CORS `origin: '*'`, and lists every in-scope operation with a unique `operationId` (required for codegen).
- **x402 contract preservation is mandatory:** `x-payment-info`, `x-bazaar`, top-level `x-x402`, `securitySchemes.x402Payment`, and `GET /.well-known/x402` must survive — breaking them removes pricing/discovery for paid AI endpoints (x402scan regression).
- Every in-scope route validates `body`, `query`, `path params`, and declared headers (`x-session-cookie`, `x-payment`) via Zod, in fixed order `authenticate → validate → handler`; invalid input returns `400` in the standard error envelope.
- Every in-scope JSON endpoint returns the canonical envelope — including middleware-originated errors (rate-limit `429`, `404`, body-parser `413`/`415`, auth `401`/`403`). Envelope applies to JSON endpoints only; streaming/binary/redirect are exempt.
- Canonical wire shapes: success `{ success: true, data: T }`; error `{ success: false, error: { code, message, type?, details? } }`; pagination `PaginatedResponse<T> = { success: true, data: T[], page: { cursor: string|null, limit, total? } }` — cursor is the sole pagination convention (offset endpoints map to it).
- Each operation declares the security scheme the route actually enforces: `bearerAuth`, `sessionCookie`, `x402Payment`, or optional-auth.
- Swagger UI is self-hosted via `swagger-ui-express` (Helmet CSP blocks CDN) at `/api-docs`, mounted before `/docs/:slug` handlers; the spec declares `servers` (localhost + production) and supports `authorize()` for `bearerAuth`. Try-it-out executes only on read-only endpoints — real-account mutations and x402-paid endpoints are marked non-executable.
- Client generation: `npm run generate:api-client` at repo root reads the committed `api/openapi.json` artifact (never a live server; fails loudly if missing/unparseable) and outputs only to `packages/api-client/`, importable as `@xactions/api-client`. Types via `openapi-typescript` plus a hand-written thin fetch wrapper that injects auth and returns a typed error union (`400 | 401 | 402 | 429 | 500`) — `402` is typed as the x402 `PaymentRequired` protocol payload, not the envelope.
- Contract honesty in CI: spec lint (`@redocly/cli`) + contract test ≥1 endpoint per route group (vitest + supertest) + regenerate-diff check — all fail on spec↔runtime drift.
- Non-breaking: standardization must not break existing consumers — x402 discovery, `x-session-cookie` transport (legacy body field normalized, not removed), domain error fields, and operator surfaces keep current semantics.

## Technical Decisions

A dedicated architecture spine exists at `planning-artifacts/architecture/xactions-api-contract-epic46/ARCHITECTURE-SPINE.md` (9 ADs) — the primary technical-decisions source. Distilled:

- **Pipeline & dependency direction:** `Zod schemas (api/schemas/**)` → `middleware/validate.js` + `openapi.js` builder → committed `api/openapi.json` (regenerated by `npm run build:openapi`, no HTTP) → Swagger UI + `openapi-typescript` → `packages/api-client` → Epic 47. Routes depend on schemas; nothing in `api/` depends on client/UI.
- **Envelope single owner:** only `api/middleware/envelope.js` serializes the envelope; handlers return `T` via `res.sendData(t)` or throw — never `res.json({success:true,...})` themselves. Exempt: streaming/binary/redirect and x402 `402` bodies.
- **Domain → HTTP error mapping:** `PlatformError` maps verbatim — `error.code`/`type`/`message` from domain, `error.details` carries the full `toEnvelope()` output (`retryAfter`, `retryAfterMs`, `isRetryable`, `suggestedAction`, `accountId`, `platform`…, no allowlist). Non-domain errors use API taxonomy codes (`VALIDATION_FAILED`, `NOT_FOUND`, `RATE_LIMITED`…); `type` is omitted when absent. Existing mappings (e.g. `checkpoints.js` `error.suggestedAction` nested field) migrate to this shape — breaking-change note accompanies an `info.version` bump.
- **Validation order is per-route:** the route's declared security scheme runs first, then Zod validation, then handler — there is no global JWT gate (`/api/ai/*` authenticates via `x402Payment`). Middleware-originated errors funnel into `envelope.js` via named mechanisms (rate-limit `handler` option, body-parser `err.type === 'entity.*'`, 404 handler, auth errors).
- **Security schemes (5):** `bearerAuth` (JWT `Authorization` header); `sessionCookie` (apiKey header `x-session-cookie` — the only canonical transport; per-route shim copies `req.body.sessionCookie` → header only when header absent and never deletes the body field, preserving current body-first precedence on dual-read handlers); `x402Payment` (apiKey header `X-PAYMENT`); `a2aApiKey` (apiKey header `X-Agent-API-Key` — agent/A2A/admin routes like `requireCheckpointManage`); optional-auth as security `[{}, {scheme}]` union where invalid credentials resolve to anonymous context, never 401.
- **Schema conventions:** request schemas do not use `.strict()` — unknown keys are stripped so legacy fields don't fail validation. Response schemas describe payload `T` only; the builder wraps `T` in canonical `SuccessResponse<T>`/`ErrorResponse` components when emitting to the spec. Dates/ids are ISO 8601 strings; pagination cursor is opaque.
- **Scope (distilled from Route Inventory, ~50 mount groups):** essentially all `/api/*` groups are in scope — including shared/edge cases: two routers share `/api/analytics` (dedupe paths, unique operationIds); only `/api/governor` is documented (legacy `/governor` mount excluded); `/api/session` currently uses express-validator (coexist, or migrate if touched); `/api/video/download` streams `video/mp4` (envelope-exempt for that endpoint); `/api/ai` merges its existing spec into the unified document keeping x402 extensions. Fixed exclusions: `POST /webhooks/*` (raw Buffer for Stripe signature), streaming/SSE endpoints (`/metrics/stream`), `/api/plugins/*` (runtime mounts — plugins self-register schemas if desired). New routes added to `server.js` must update the inventory in the same PR.
- **Deployment:** full spec/UI is mandatory on `api/server.js`; `api/serverless.js` (Vercel) serves the same document but `info.description` must note some paths return 503 on serverless.
- **Try-it-out enforcement:** baseline `supportedSubmitMethods: ['get']`; per-operation granularity via a swagger-ui plugin reading the `x-tryitout: false` vendor extension.
- **Stack (pinned):** zod 4.6.5, @asteasolutions/zod-to-openapi 9.1.0, swagger-ui-express 5.0.1, openapi-typescript 7.13.0, @redocly/cli 2.54.2, supertest ^6.3.4 (repo-pinned). Two landmines: pinning `zod@4` bumps a transitive zod 3.x used by `src/analytics/viralStatsStore.js` — audit it in the same PR; enabling npm workspaces rewires module resolution — run an install audit (`packages/xactions-mcp`, phantom deps, dual-lockfile decision) before committing the lockfile.

## Cross-Story Dependencies

- **Build order is 46.2 → 46.1 → 46.3** (not numeric order): spec `paths` coverage in 46.1 cannot be verified until Zod schemas exist (46.2); client generation (46.3) runs against the final stable artifact.
- Epic 47 consumes `@xactions/api-client`; this epic delivers only the package — migrating existing fetch calls in the dashboard/frontend is Epic 47 scope.
- Inherited invariants from the hybrid-scraping spine: the domain error shape/vocabulary and operator surfaces (`/api/governor`, `/api/checkpoints`, `/metrics/stream`) keep their published response fields — the HTTP layer maps them, never reshapes.
