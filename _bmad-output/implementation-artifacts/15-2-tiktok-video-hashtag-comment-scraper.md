# Story 15.2: TikTok Video, Hashtag & Comment Scraper with Anti-Bot Payload Validation

Status: ready-for-review

## ⚠️ Critical Constraints / Architecture Variance

The following decisions are non-negotiable and override any earlier language in this story or external references:

1. **Build on top of Epic 13.1 (done).** `src/core/signer-pool.js` provides `PreSignedTokenRing` and `SignerWorkerPagePool` for the Tiered Hybrid Signer Engine. TikTok is the first consumer of the Tier-2 worker page pool for dynamic `a_bogus` signing. Do not recreate a signer.
2. **TikTok requires `requiresAuth = true` at platform level** (AD-3 rule 2, AD-8). Therefore all actions default to sticky IP per `accountId`. A single `tiktok-guest` account may be registered in `AccountPool` if no authenticated session is supplied, but the crawler still resolves an `accountId` and a sticky proxy. Failure to register `tiktok-guest` before the first real-API test will cause `AbstractCrawler.start()` to throw `XACT_4010` (see AC-7).
3. **No plain-text `msToken` or `a_bogus` logged.** Token values, cookies, and signed query strings must never appear in logs, errors, or envelopes (NFR-4, AD-14).
4. **False 200 OK defense is mandatory.** TikTok's WAF often returns HTTP 200 with an empty body or JSON `{ status_code: ..., error: ... }`. The `TikTokPlatformResponseValidator` must treat `error !== 0` or an anomalously empty feed as a bot challenge and trigger proxy rotation, not silent data corruption (FR-75, AD-9). Use existing error codes only: `XACT_4030` for `BotChallengeError`, `XACT_4290` for `RateLimitError`, `XACT_4001` for invalid payload. Do not invent `XACT_4003` (it does not exist in `src/core/error-envelope.js`).
5. **No new Prisma models.** Reuse existing `Post` and `Comment` tables with Namespaced IDs: `tiktok:<videoId>` for videos and `tiktok:<videoId>:<commentId>` for comments (AD-4).
6. **HTTP client is `got-scraping` by default.** TikTok Web API calls must use `got-scraping` (TLS/JA4 spoofing) through `ProxyIpPool` with a SOCKS5/HTTP proxy agent. `TikTokClient` must set `client: 'got'` in its constructor so `AbstractApiClient.#getDefaultHttpClient()` uses `gotScraping`. Do not mix `got-scraping` and `undici` in the same request pipeline (AD-1 rule 4).
7. **Worker page pool is used only for signing, not browsing.** `a_bogus` and `msToken` are generated by evaluating the signing script on a `SignerWorkerPagePool` page. The actual feed/comments fetch is a pure HTTP call to avoid full browser overhead (AD-1, NFR-11). Signing is done through `AbstractApiClient.requestWithSign()` with `signType: 'page'`, or by overriding `sign()` and returning `{ query: { a_bogus, msToken } }`.
8. **Comment tree must be topologically sorted before storage.** Insert root comments (depth 0) before sub-replies (depth 1+) to avoid FK violations (AD-6).

## Acceptance Criteria

### AC-1: TikTokCrawler registers `search`, `hashtag_feed`, `post_detail`, and `get_post_comments` actions with dispatcher aliases

- **Given** a new `TikTokCrawler` in `src/scrapers/social/tiktok/crawler.js` extending `AbstractCrawler`
- **When** the constructor runs
- **Then** it registers the following snake_case actions in `ActionRegistry`:
  - `search` — search TikTok by keyword (exposed to consumers as `search_videos`)
  - `hashtag_feed` — fetch videos for a hashtag
  - `post_detail` — fetch a single video's metadata (exposed to consumers as `video_detail`)
  - `get_post_comments` — fetch root and paginated replies for a video (exposed to consumers as `video_comments`)
- **And** `listActions()` returns `ActionDescriptor[]` with correct `requiredArgs`, `optionalArgs`, `outputType`, `example`, and resolved `requiresAuth: true`
- **And** `outputType` is `'PostItem[]'` for `search`/`hashtag_feed`, `'PostItem'` for `post_detail`, and `'{ comments: CommentItem[], hasMore: boolean, cursor?: string }'` for `get_post_comments`
- **And** `src/scrapers/index.js` provides a `TIKTOK_ACTION_MAP` mapping consumer-facing action names to internal names: `search`/`search_videos` → `search`, `hashtag`/`hashtag_feed` → `hashtag_feed`, `post`/`post_detail`/`video_detail` → `post_detail`, `comments`/`get_post_comments`/`video_comments` → `get_post_comments`

### AC-2: `TikTokClient` signs and executes HTTP requests using the Tiered Hybrid Signer

- **Given** `TikTokClient` in `src/scrapers/social/tiktok/client.js` extending `AbstractApiClient`
- **When** calling `request(method, url, options)` or `sign(params)`
- **Then** `TikTokClient` uses `PreSignedTokenRing` for session token `msToken`
- **And** uses `SignerWorkerPagePool.evaluate(...)` to generate dynamic query parameter `a_bogus` for each request (or batch)
- **And** injects required headers: `User-Agent` with a current mobile/desktop TikTok-compatible UA, `Referer: https://www.tiktok.com/`, and `Accept-Language: en-US,en;q=0.9` (or `vi-VN` when target is VN market)
- **And** passes the signed URL to `got-scraping` through the proxy agent from `ProxyIpPool`
- **And** returns raw response data in `PlatformResponse` shape `{ statusCode, data, headers, url }`

### AC-3a: `search({ query, count, cursor })` returns normalized PostItem[]

- **Given** a keyword
- **When** calling `crawler.start({ action: 'search', args: { query, count, cursor }, session })` or `scrape('tiktok', 'search_videos', { ... })`
- **Then** `TikTokClient` calls the TikTok Web search API endpoint with signed `a_bogus` and `msToken`

### AC-3b: `hashtag_feed({ tag, count, cursor })` returns normalized PostItem[]

- **Given** a hashtag (without `#`)
- **When** calling `crawler.start({ action: 'hashtag_feed', args: { tag, count, cursor }, session })` or `scrape('tiktok', 'hashtag_feed', { ... })`
- **Then** `TikTokClient` calls the appropriate TikTok Web API endpoint with signed `a_bogus` and `msToken`
- **And** the response passes `TikTokPlatformResponseValidator.isValidPayload()`
- **And** if `error !== 0` or `status_code !== 0` or the feed items array is anomalously empty, the validator returns `isBotChallenge: true` or `isRateLimit: true` and the crawler throws a `BotChallengeError` (`XACT_4030`) or `RateLimitError` (`XACT_4290`) with `suggestedAction: 'rotate_proxy'`
- **And** on valid payload, items are normalized into `PostItem[]` with:
  - `id: 'tiktok:<videoId>`
  - `platform: 'tiktok'`
  - `externalId: <videoId>`
  - `category: 'social'`
  - `authorId`, `authorName`, `authorAvatar`
  - `content: caption text`
  - `mediaUrls: [video download URL / cover image]`
  - `likesCount`, `repostsCount` (shares), `repliesCount` (comment count), `viewsCount`
  - `metadata: { duration, hashtags, musicId, musicTitle, region, awemeId, videoHeight, videoWidth, sourceMethod }`
  - `publishedAt` from `createTime`
  - `crawledAt: now`
- **And** `count` is clamped to `[1, 35]` per request and paginated with `cursor`
- **And** `hasMore` and `cursor` are returned for resumption via `CrawlCheckpoint`
- **And** the batch is stored via `PrismaStore.storeBatch()` and a thin event is emitted to `stream:social:raw_posts` when `REDIS_STREAM_ENABLED=true`

### AC-4: `post_detail({ videoId, url })` returns a single PostItem

- **Given** a numeric `videoId` (aweme_id) or a TikTok share URL
- **When** calling `crawler.start({ action: 'post_detail', args: { videoId | url }, session })` or `scrape('tiktok', 'video_detail', { ... })`
- **Then** `TikTokClient` resolves the video ID and calls the item detail endpoint with `a_bogus` + `msToken`
- **And** the response passes payload validation
- **And** on valid payload, returns a `PostItem` with the same normalized schema as AC-3
- **And** a `CrawlCheckpoint` is written with `targetType: 'video'`, `targetKey: <videoId>`, `status: 'completed'`

### AC-5: `get_post_comments({ videoId, maxComments, maxDepth, cursor })` extracts a paginated comment tree

- **Given** a valid `videoId` and optional `maxComments` (default `50`, clamped `[1, 200]`), `maxDepth` (default `1`, clamped `[1, 3]`), and `cursor`
- **When** calling `crawler.start({ action: 'get_post_comments', args: { videoId, maxComments, maxDepth, cursor }, session })` or `scrape('tiktok', 'video_comments', { ... })`
- **Then** `TikTokClient` calls the TikTok comment list endpoint with `a_bogus` + `msToken`
- **And** the response passes payload validation
- **And** root comments are normalized into `CommentItem[]` with `depth: 0` and `parentCommentId: null`
- **And** if `maxDepth > 1` and `reply_total > 0`, paginates through reply pages and normalizes sub-replies with:
  - `id: 'tiktok:<videoId>:<commentId>'`
  - `platform: 'tiktok'`
  - `postId: 'tiktok:<videoId>'`
  - `parentCommentId: 'tiktok:<videoId>:<parentCommentId>'` for depth >= 1
  - `depth` matching the reply nesting level
  - `content`, `likesCount`, `authorId`, `authorName`, `authorAvatar`, `publishedAt`
- **And** the comment tree is topologically sorted by `depth` before being stored via `PrismaStore.storeCommentBatch()`
- **And** the crawler detects and breaks circular parent references (a comment cannot be its own ancestor)
- **And** `hasMore` and `cursor` are returned for resumption

### AC-6: Anti-Bot Payload Validation prevents silent empty data

- **Given** `TikTokPlatformResponseValidator` in `src/scrapers/social/tiktok/validator.js`
- **When** the TikTok API returns HTTP 200 with `{ status_code: 10000 }`, `{ error: { code: ..., message: ... } }`, empty `item_list`, or an HTML challenge page
- **Then** `isValidPayload()` returns `false`
- **And** `isBotChallenge()` returns `true` for WAF/captcha responses
- **And** `isRateLimit()` returns `true` for `status_code` indicating rate limiting
- **And** the crawler throws the appropriate `PlatformError` with a `suggestedAction` of `rotate_proxy` (no-auth/quest) or `hibernate_account` (auth account), never silent empty `PostItem[]`

### AC-7: Integration with `scrape()` dispatcher and package exports

- **Given** `src/scrapers/index.js` is the unified dispatcher
- **When** the platform `tiktok` is requested
- **Then** `src/scrapers/index.js` imports and instantiates `TikTokCrawler` from `src/scrapers/social/tiktok/index.js`
- **And** `package.json` exports include `"./scrapers/social/tiktok": "./src/scrapers/social/tiktok/index.js"`
- **And** `src/scrapers/social/tiktok/index.js` exports `TikTokClient`, `TikTokCrawler`, `TikTokPlatformResponseValidator`, and the normalizer helpers

### AC-8: Tests are real-API red-phase and no-mock

- **Given** the XActions no-mock testing policy
- **When** running `vitest run tests/scrapers/social/tiktok/`
- **Then** all tests hit real TikTok Web API endpoints or the worker signer in a real browser page
- **And** tests cover: signer produces non-empty `a_bogus` and `msToken`, `search`/`search_videos` returns valid `PostItem[]`, `hashtag_feed` returns `PostItem[]`, `post_detail`/`video_detail` returns a `PostItem`, and `get_post_comments`/`video_comments` returns `CommentItem[]` with correct `depth`
- **And** tests verify that a mocked `/api/...` response with `error !== 0` is rejected by the validator

## Dev Notes

### Relevant Architecture Patterns and Constraints

- **Tiered Hybrid Signer (AD-1):** Use `PreSignedTokenRing` for `msToken` and `SignerWorkerPagePool.evaluate(script, args)` for `a_bogus`. The signing script is expected to be loaded at runtime from an in-repo script at `src/scrapers/social/tiktok/signer-scripts/a_bogus.js` or similar. If the script is not available during red-phase, tests must fail (red) and the dev agent must capture a real signing script from a TikTok web session or use a known reverse-engineered implementation. Implement signing by calling `this.requestWithSign('GET', url, { signType: 'page', script: this.#signerScript, args: [url, params] })` or by overriding `sign()` and returning `{ query: { a_bogus, msToken } }`.
- **Proxy & Auth (AD-3, AD-5):** TikTok is an auth-required platform. The crawler must resolve `accountId` from `AccountPool` and use `proxyPool.getStickyProxy(accountId)`. If no account is available, `AbstractCrawler.start()` throws `XACT_4010`. Tests must pre-register `tiktok-guest` via `accountPool.registerAccounts('tiktok', ['tiktok-guest'])` and set `governor.setPlatformLimit('tiktok', { safeRequestsPerMinute: 15, requiresAuth: true })`. If `sessionManager` provides a TikTok session cookie, pass it through `updateCookies()`.
- **HTTP Client (AD-1 rule 4):** Use `got-scraping` only. `TikTokClient` constructor must pass `client: 'got'` to `super()` so `AbstractApiClient` uses `gotScraping` with `proxyUrl` from `getProxyAgent(proxy, { client: 'got' })`. Do not mix `undici`.
- **Anti-Bot Validation (AD-9):** Always validate payload before normalizing. Do not rely solely on HTTP status.
- **Storage (AD-4, AD-6):** Namespaced IDs and topological comment insertion are mandatory.
- **Real Implementations Only (CLAUDE.md testing rule 1):** No mocks, stubs, or fakes. Tests must call real TikTok endpoints or real signer worker pages.

- **Framework:** Vitest 4.x, no mocks.
- **Timeouts:** 30s per test, 30s for hooks (or longer for real signer warm-up if needed).
