- (direction) Adopt ARCHITECTURE-SPINE.md as canonical contract source. Single-Gateway Facade: POST /api/platform/:platform/scrape is THE public scrape route; auth + sync/async are cross-cutting seams, never per-consumer branches.
- (capability) CAP-1 Unified scrape entry: any consumer calls POST /api/platform/:platform/scrape with (action, options, mode) and reaches the same scrape(platform,action,options) dispatcher — no consumer-named routes.
- (capability) CAP-2 Service authentication: machine consumers authenticate via Bearer token → server-derived consumer_id (jev/nowing/chainlens/internal); user-JWT lane remains for dashboard; x402 covers third-party/premium.
- (capability) CAP-3 Sync/async dispatch: mode:'sync' runs scrape() in-process <1.5s; mode:'async' queues Bull job → poll /api/ai/action/status/:id; auto-degrade sync→async returns 202+operationId+Retry-After.
- (capability) CAP-4 Unified envelope: every call returns {success, mode, metadata{request_id,...}, stream{...}, preview[≤10 verbatim slice of data], data[]} with snake_case fields.
- (capability) CAP-5 Per-consumer rate-limit isolation: DistributedTokenBucket keyed on derived consumer_id:platform:action — one consumer's volume never starves another.
- (capability) CAP-6 Batch dispatch: platform:'all'|string[] fans out via UniversalActionDispatcher, returns same envelope with results[] per platform.
- (capability) CAP-7 Self-discovery: openapi.json + x_actions_list surface every (platform,action,syncCapable) so consumers learn the contract without reading code.
- (constraint) C-1 consumer_id is derived server-side from Bearer credential — never trusted from X-Consumer-Id header (spoofing would break C-5 isolation).
- (constraint) C-2 Sync calls hard-ceiling at 1.5s and degrade to 202 — never extend the window (reintroduces jev's fork-trigger hang).
- (constraint) C-3 XActions never proxies sub-second data (pumpportal WS, Solana RPC, trade tape) — those stay consumer-owned.
- (constraint) C-4 Domain-specific fields (crypto: dev_paid_order, bonding_curve, realized_pnl) live in data/context payload only — never in ThinEvent or envelope core.
- (constraint) C-5 VALID_CONSUMER_IDS stays frozen ['nowing','chainlens','internal']; new named consumers come from env config, not code.
- (constraint) C-6 x402 route-config must explicitly cover POST /api/platform/:platform/scrape (it currently only maps /api/ai/* + /api/scripts/*).
- (decision) Non-goal NG-1: sub-second real-time data plane (pumpportal WS mints, Helius/Triton gRPC, Solana RPC) — consumer-owned, not XActions.
- (decision) Non-goal NG-2: Telegram MTProto vs Bot API transport — deferred to D4 spec, not decided here.
- (decision) Non-goal NG-3: per-consumer SLA/billing tiers beyond x402 pay-per-call — wait for real usage data.
- (decision) Non-goal NG-4: forcing jev to migrate its in-repo PumpFunCrawler — consumer-side choice; gateway only needs to make sync path preferable.
- (decision) Non-goal NG-5: per-platform status routes — /api/ai/action/status/:id is the ONLY async status endpoint.

- (decision) OQ-A resolved: UniversalActionDispatcher already uses Promise.allSettled (dispatcher.js:296) — batch is parallel. 1.5s ceiling applies per-platform (each platform's own scrape call); batch total is bounded by slowest single platform, not sum. No new rule needed — ratify existing behavior.
- (decision) OQ-B resolved: Bearer is all-or-nothing per consumer. Scoped tokens (consumer=X&actions=Y) add an authz matrix with no current need — every named consumer is trusted internal. If untrusted-scoped access is needed later, it becomes a NEW consumer class (e.g. 'partner-limited') via env config, not Bearer parsing. Matches C-5.
- (decision) OQ-C resolved: x402 settles post-response (per @x402/express README: 'Handles settlement after successful response'). Verify pre-handler, settle on 200. For sync: payment verified at request time, settled after scrape returns. For async: payment verified at enqueue, settled when 202 returned — consumer pays for the job accept, not the result. This matches pay-per-call semantics, not pay-per-result.
