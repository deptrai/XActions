Epic 34 Architecture Spine — Update Report 2026-09-08

What was changed

The architecture spine ARCHITECTURE-SPINE.md and its companion metrics-catalog.md were updated to close the findings raised by the 2026-09-08 Reviewer Gate (rubric-walker + tech-currency + adversarial).

Key amendments

  1. AD-23 — Redis Stream retention fixed
  2. Removed invalid "7-day TTL" language (Redis Streams have no per-entry TTL).
  3. Set MAXLEN ~ 1000000 and defined rolling retention via XTRIM ... MINID ~ <seven_days_ago_ms> in the consumer.

  4. Declared telemetry-consumer.js as a native Redis Stream consumer-group reader (XREADGROUP + XACK) — not a Bull worker.

  5. AD-24 — Emission primitive fixed

  6. setImmediate only; queueMicrotask removed to prevent event-loop starvation and NFR-19 violations.

  7. AD-25 — Centralized instrumentation tightened

  8. Added TelemetryContext threaded through session.telemetry so AbstractCrawler.start() and AbstractApiClient.request() contribute to one correlated run.

  9. Corrected base-client.js filename (not base-api-client.js).

  10. AD-26 — Knock-out gate data contract fixed

  11. Gate field names now map 1:1 to metrics-catalog.md metric paths (true_success_rate, field_fill_rate, false_200_rate, schema_integrity_rate).

  12. AD-27 — Thin-event extension points corrected

  13. benchmark_health/benchmark_alert belong in ThinEvent typedef and RedisStreamPublisher.publish() — not MetadataSchemaRegistry or prisma-store.js.

  14. ThinEvent gains optional scraperId; fallback is "UNKNOWN" (not "B").

  15. AD-28 — Category map aligned to brownfield code

  16. Catalog profiles now map to CATEGORY_VALUES (ecom, realestate, recruitment, b2b, fnb_merchant, healthcare, legal, etc.).

  17. AD-29 — Two-phase correlated telemetry envelope (new)

  18. telemetry:request emitted by AbstractApiClient.request() with transport metrics.
  19. telemetry:run emitted by AbstractCrawler.start() with run shape.

  20. Redis XADD fields are flat Record<string, string>.

  21. AD-30 — Validator-to-telemetry bridge (new)

  22. AbstractPlatformResponseValidator.validateResponse() returns { isValid, isFalse200, isCheckpoint, isRateLimit, isAuthExpired, reason? } and writes into the shared telemetry context.

  23. AD-31 — Single-writer tier state machine (new)

  24. BenchmarkStateManager is the sole mutator of hash:scraper:health_tier; ScraperHealthScore gains consecutiveCleanRuns and requalifiedAt.

  25. 24-hour knock-out window ignores pre-requalifiedAt failures to stop demote/promote oscillation.

  26. AD-32 — Health tier cache (new)

    • In-memory HealthTierCache with 30s refresh; PG warmup on startup; fail-safe fallback to "C" if a recent Tier C record exists, otherwise "UNKNOWN".

  27. AD-33 — Item count + canary isolation (new)

    • extractItemCount(result) handles { items, posts, data, records, results, count } return shapes.
    • Canary runs use session.isCanary = true; governor bypasses account velocity/quota for canary traffic.

  28. AD-34 — Scraper identity + category binding (new)

    • Every crawler declares scraperId (<platform>-<variant>) and category (a CATEGORY_VALUES entry); both are stamped on every event.

Structural seed changes

  • Domain logic: src/benchmark/ instead of src/services/benchmark/.
  • Background workers: api/services/benchmark/ (consistent with existing api/services/retentionScheduler.js and jobQueue.js).
  • CLI command: src/cli/commands/benchmark.js (consistent with existing registerBenchmarkCommand pattern).

Stack corrections

  • Node.js: >= 20.18.1 (was >= 18; project package.json enforces this, Node 18 is EOL).
  • Redis Client: explicitly node-redis 4.x (redis@^4.6.11).
  • node-cron 4.x: primary scheduling pattern.
  • Bull 4.x: discrete job enqueueing only, not a Redis Stream consumer.
